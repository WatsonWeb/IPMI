## Agent architecture and sequential execution

Use this architecture for all implementation tasks in this plan:

1. **Lead orchestrator — GPT-6 Astra, Ultra reasoning.** The orchestrator selects the next ready task according to dependencies, creates its subagent, monitors progress and blockers, and reviews completion evidence and the commit/push result before moving on.
2. **Fresh per-task subagent — GPT-6 Astra, Medium reasoning.** Create a new subagent for each numbered task. Give it the task ID and document path, this master's workflow/safeguards, and only the dependency outcomes needed for that task. Have it read its task-specific document before starting. Do not reuse a previous task's worker or inherit the full conversation history; keep working context focused to reduce context bloat and compaction.
3. **One task at a time.** Do not run implementation tasks or task subagents in parallel. The active task subagent has exclusive control of Chrome's Webflow Designer and CMS; the orchestrator monitors through progress reports without interacting with the editor at the same time. Do not create parallel browser workers or overlapping nested subagents.
4. **Commit and push after completion.** Each subagent performs the task's acceptance checks, updates its task doc and the master status with implementation evidence, then creates and pushes a task-scoped commit using a Conventional Commits message. For browser-only changes, commit the documentation/evidence of the Webflow changes; a Git commit alone does not capture Webflow state. Preserve unrelated work and the staging/versioned-asset safeguards, including during any push-triggered deployment.
5. **Explicit handoff before the next task.** The subagent reports the outcome, checks, staging URLs, changed files, commit SHA, pushed branch/remote, and remaining dependencies, then releases browser control. The orchestrator verifies the handoff and successful push before creating the next fresh subagent. If a task is blocked, record the blocker and end that worker's activity before selecting another ready task; do not mark it complete. A later attempt uses another fresh subagent with the saved task record.

These execution rules apply even when two tasks have independent dependencies. Dependency tracking does not authorize concurrent task execution.
